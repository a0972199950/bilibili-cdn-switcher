# /analyze-cdn [國家代碼]

把 `/collect-speedtest-mail`（或 `/cdn-speedtest`）存下的各份 `*-summary.json` 合起來看，產生一份**分析報告**給使用者讀。
**這個技能不改任何專案檔案**：要不要照建議更新 `src/cdn-list.json`，等使用者讀完報告、明確說要更新，才做第 5 節。

以下 `$SK` = `.claude/skills/analyze-cdn`，`$R` = `cdn-speedtest-results`（gitignored，含出口 IP），都在 repo 根目錄執行。腳本只用 Python 標準函式庫，一律 `python -I`。

## 1. 準備

1. 國家代碼沒給：`ls $R` 列出各國份數，問使用者要分析哪一國（只有 1–2 份的國家先提醒樣本不足）。
2. 若使用者可能有新的測速信還沒收，提醒可以先跑 `/collect-speedtest-mail`（不要自己決定跑）。

## 2. 產生報告

```bash
python -I $SK/analyze.py <國家> [--exclude rid,...] [--include rid,...] [--primary-isp ASxxxx]
```

`--primary-isp` 省略時讀 `$SK/primary-isp.json` 的該國設定（目前 TW = AS3462 中華電信）。主要 ISP 的第一梯隊在清單排最前、預設從它選；使用者說某國哪家 ISP 佔多數時，更新這個檔案。

輸出 `$R/_analysis/<國家>-<yyyymmdd-HHMM>.md`（分析報告，不含 IP）與同名 `.json`（建議清單，第 5 節用），最後一行 `OUTPUT <路徑>`。

腳本做的事（報告裡都有寫明規則，回報時不必重述）：

- **線路**：同 ISP 且同出口 IP（或同 /24、同網卡）的報告是同一戶重複測試，合併成 1 個樣本；所有比例、重抽樣都以線路計。IP 只在記憶體比對，不寫進報告。
- **自動排除**量測本身壞掉的報告（快篩通過 < 30 個、細測全成功 < 15 個、上限 < 30 Mbps）；其他疑點只標示。
- **網路類型**依網卡名稱重新判斷（GUI 的 `netinfo.py` 用 `LTE` 比對網卡名，會把 `Realtek` 有線網卡誤判成行動網路）。
- **節點分數**：每份報告中第一梯隊 = 1、可用／差 = 平均 ÷ 該報告最快穩定節點、不穩定 × 0.5、失效／沒進細測 = 0，再以線路平均。
- **離群報告**：與其他線路共識的 Spearman 相關過低、或前 10 名幾乎不重疊；再看同 ISP 其他線路是否也一樣 → **ISP 通案**或**個案**。
- **極端值**（爆發／崩潰的節點）：依發生的線路歸類為個案、ISP 通案、尖峰通案、普遍現象、零星。
- **分群**：每家 ≥ 3 條線路的 ISP 單獨成群（指定的主要 ISP 2 條就成群），其餘線路合併成「其他」。一個國家常有「不同 ISP 偏好完全不同」的情況（台灣：中華電信 vs 其他），不分群的話節點會被別群的 0 分拉成「差」，清單湊不滿、品質下降。
- **跨報告分級**（每群內，比照單份報告的分級）：以分數最高的節點為基準逐線路配對比較，差距在 2 倍標準誤內且分數 ≥ 基準 80% → 第一梯隊；≥ 基準一半 → 可用；其餘 → 差。各群取聯集：任一群第一梯隊 → 第一梯隊；否則任一群可用 → 可用。進細測的線路一半以上不穩定 → 不穩定；任一份 403 只能播熱門 → 不列。
- **清單**（與 `/cdn-speedtest` 單份報告的規則相同）：先取第一梯隊（主要 ISP 那一群的排最前、依該群分數，其餘依整體分數），同一個 CDN 池（叢集，例如 `cn-hk-eq-*`、華為一般池）最多 2 個，剩下名額讓給其他池；第一梯隊不足 10 個才補「可用」；不穩定、差不列，不足 10 個就少列。預設 = 主要 ISP 那一群（沒指定就全部）在清單中的第一梯隊裡，沒有不穩定紀錄、速度穩定（sd/平均 ≤ 0.3）、TTFB 不高者分數最高的。
- **主要 ISP 的代價**：預設對其他群常是「差」，報告會標 ⚠。擴充的自動備援只在錯誤／卡住時切到 B 站自己的備援網址，不會自己換到清單裡的節點，所以其他 ISP 的使用者剛安裝要靠手動測速改選；判讀要把這點列為已知風險（直到擴充有安裝後自動測速或依 ISP 選預設）。
- **各 ISP 的預設**：同樣規則只用該 ISP 的線路算，附該 ISP 的樣本等級與「預設穩定度」（重抽樣選出同一個預設的比例），給之後「依 ISP 選預設」用。
- **清單覆蓋表**：每份報告在清單裡找得到的最佳／次佳節點分數，分 ISP 列出，用來看清單有沒有照顧到某家 ISP（診斷用，不影響挑選）。
- **樣本**：< 3 條線路「不足」、3–5「偏少」、≥ 6「尚可」（全國與各 ISP 都這樣判斷），另列 ISP 偏重、重複測試、時段缺口，以及以線路重抽樣（bootstrap）的入選率。
- **ISP 名稱**：ip-api 的 `isp`（註冊公司名，例如 `Chunghwa Telecom Co., Ltd.`）為主，與 GUI 信件標題用的 AS 名稱（ipinfo `org`，例如 `AS3462 Data Communication Business Group`）不同時一併列出。

## 3. 判讀（Claude 要做的事）

讀整份報告（它不含 IP，可以讀進上下文；**不要**讀原始 `summary.json` 的 `env.exit.ip` 等欄位）。逐項檢查後，必要時調整排除名單重跑：

- **離群報告**：被標「個案」且有量測疑點（並行數手動、互搶頻寬、DNS 改道、上限極低…）而且拿掉它清單會變動 → 考慮 `--exclude` 重跑；被標「ISP 通案」的**不要排除**，它代表該 ISP 使用者的真實體驗。被自動排除、但你判斷其實可用的 → `--include`。每個決定都要在判讀寫理由。
- **極端值**：「個案」不據以加減節點；「ISP 通案」要看清單覆蓋表的該 ISP 欄，覆蓋差就在判讀中點出（清單規則不為單一 ISP 破例，改由「依 ISP 選預設」解決）；「普遍現象」的崩潰代表節點本身時好時壞，不適合當預設。
- **各 ISP 預設**：只有樣本「尚可」且預設穩定度高的 ISP 才建議採用；其餘明寫「樣本不足，暫不採用」，並列出還需要幾條線路。
- **樣本**：「不足」時判讀第一句就寫「樣本不足，不建議據此更新」，只給參考清單與該補哪些樣本；「偏少」要指出哪些名次不穩（入選率 < 50%）。
- 數據看起來不合理（例如某池全部 0 分、某份報告大量 DNS 失敗）時，回頭查該報告的 `REPORT.md` 再判斷，不要硬套規則。

然後用 Edit 把報告最後的 `<!-- CLAUDE: … -->` 換成「## 7. 判讀」的內文（繁體中文、條列為主），涵蓋：

1. **結論一句話**：建議更新／暫不更新／樣本不足僅供參考。
2. **國家特徵**：主要 ISP 與各自偏好的 CDN 池、尖峰時段差異、常見失效。
3. **離群與極端值的處置**：哪些排除、哪些保留、個案還是通案、理由。
4. **建議清單與預設**：節點（預設在第一個）與入選理由；和目前清單相比換掉哪些、為什麼。
5. **各 ISP 預設**：哪些 ISP 已可採用、哪些樣本不足。
6. **風險與待補樣本**：哪些 ISP／時段／城市還缺、哪些名次可能變動。

有用 `--exclude`／`--include` 重跑時，舊的報告檔（同國家較早時間的 `.md`／`.json`）刪掉，只留最後一份。

## 4. 回報

告訴使用者報告路徑，並用幾行摘要：結論、樣本狀況、建議預設與主要變動、需要使用者決定的事（例如某份報告要不要排除）。
**明確說「尚未修改 `src/cdn-list.json`，讀完報告後告訴我要不要更新」**，然後停下來等使用者。

## 5. 更新節點庫（只在使用者讀完報告、明確要求後）

1. 讀最新的 `$R/_analysis/<國家>-*.json`：`nodes`（第一個是預設）、`not_in_options`。使用者對清單有修改意見就照使用者的。
2. 改 `src/cdn-list.json`：
   - `countries` 中該國的 `nodes` 換成新清單（第一項 = 預設）。
   - 國家還不存在：新增 `{ "code", "dial", "name": {zh_TW, zh_CN, en, ja, ko} }`，`dial` 是國際電話區碼（對應 B 站 zone API 的 `country_code`），名稱五語都要寫。
   - `not_in_options` 的節點要加進 `options`（`value`、`name` 技術代號、`pool` 對應 `pools` 的 key；新池要在 `pools` 補五語標籤）。
   - 確認 JSON 合法：`node -e "JSON.parse(require('fs').readFileSync('src/cdn-list.json','utf8'))"`。
3. 這是使用者感受得到的改動：依 `agent.md` 在 `src/changelog.json` 的 `unreleased` 追加一條 `fix` 或 `feature`（五語，寫給使用者看，例如「更新台灣的建議節點清單與預設節點，依實測改用較快的節點」），再 `npm run changelog:validate`。
4. 給使用者看 diff；commit／push 只在使用者要求時做，並遵守 `agent.md` 的 commit 規則（作者 `John H`、不加 AI 署名）。

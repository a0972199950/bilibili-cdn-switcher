# /cdn-speedtest

在使用者**當下所在國家的當地網路**上，量測本技能節點清單 `nodes.json` 的 299 個 B 站點播 CDN 節點，兩階段篩選後給出「排名 + 分級」與「依 CDN 池分散的建議前 10 名 + 預設節點」。

所有腳本都在本資料夾內（`speedtest.py`、`videos.py`、`bili.py`、`netinfo.py`、`nodes.json`），只用 Python 標準函式庫，不依賴 `research/` 或專案設定。節點清單只讀 `nodes.json`（`source`：`project`=擴充內建、`extra`=其他來源；要增減節點就改這個檔案）。以下 `$SK` 代表 `.claude/skills/cdn-speedtest`（在 repo 根目錄執行時）。

## 0. 前置確認（每次開始前）

1. **Python**：`python3 --version`（3.8 以上即可，不需 pip 套件）。DNS 檢查會用到系統 `nslookup`。
2. **偵測網路環境**（不必請使用者報國家）：

   ```bash
   python3 $SK/speedtest.py detect
   ```

   會印出出口 IP／國家／ISP、系統 DNS、替使用者查詢的解析器（國家、是否帶 ECS）、DNS 檢查結論、登入狀態，最後一行 `DETECTED_COUNTRY=XX`。
3. **向使用者確認後才開始**（用 AskUserQuestion 或直接問）：
   「偵測到你目前在 **XX**（ISP：…，出口 IP：…），要測 XX 嗎？」，並附上：
   - DNS 檢查結論（若有 ⚠，見下方「DNS 陷阱」，一併問要不要改用當地 ISP DNS）；
   - 登入狀態（未登入只能測 ≤480P）；
   - 提醒：請關閉 VPN／代理；**手機漫遊的數據通常從母國出口**，請用當地 Wi-Fi 或當地 SIM；出口若是機房／VPN 網路，結果不代表當地家用使用者。
   使用者確認國家後，用該國家代碼執行（第 1 節）。使用者說偵測錯了，就照使用者說的國家代碼並加 `--ignore-country-mismatch`。
4. **Cookie（要測 1080P 以上必須登入）**：腳本先讀環境變數 `BILI_COOKIE`，否則讀目前工作目錄的 `.env.local`（`BILI_COOKIE=...` 一行）。**絕對不要把 cookie 印出、貼進對話或寫進任何檔案以外的地方**；檢查時只看「登入：是／否」。

### DNS 陷阱（實際踩過）

2026-10-02 在新加坡經 VPN 模擬台灣時發現：**開 VPN 後系統 DNS 變成 Cloudflare 公共解析器，且不帶 ECS**（EDNS Client Subnet）。B 站部分節點網域是 GeoDNS（依「查詢者所在地」回傳不同 IP，例如 `upos-sz-mirrorali`、`upos-hz-mirrorakam`），解析器不在當地又不帶 ECS 時，會被分到**解析器所在地**的機器，而不是使用者所在地的機器，測速結果就不代表當地。當時同一網域，系統 DNS 與中華電信 DNS（168.95.1.1）解析出的 IP 不同，最後改用當地 ISP DNS 解析節點才正確。

腳本的處理：

- `detect`／`env` 會查 `o-o.myaddr.l.google.com` 的 TXT，取得「替你向 Google 權威 DNS 查詢的解析器出口 IP」與 ECS 子網，再比對它們的國家與出口國家：
  - 帶 ECS 且 ECS 子網在當地 → OK；解析器本身在當地 → OK；
  - 否則 ⚠：GeoDNS 節點可能被分到錯的機器。
- `all` 遇到 ⚠ 且沒指定 `--dns` 時會 **exit 6** 停下來。Claude 要問使用者：
  - 改用 Google DoH 並帶自己出口 IP 的 ECS：`--dns doh`（最省事，不必知道當地 ISP 的 DNS）。
  - 改用當地 ISP 的 DNS：`--dns <當地 ISP DNS IP>`（不知道 IP 可查當地 ISP 公布的 DNS，例如台灣中華電信 168.95.1.1；或看路由器／DHCP 給的 DNS）。之後節點網域都用它解析，連線的 TLS 仍用原網域。
  - 或確認當地本來就用公共 DNS（使用者實際看影片也是這樣解析），加 `--ignore-dns-mismatch` 繼續。
- 可加 `--isp-dns <IP>` 讓 `env` 並列比較「系統 DNS vs 當地 ISP DNS」對關鍵節點的解析結果。

## 1. 執行（建議：`all` + 分段續跑）

Claude Code 前景指令 10 分鐘會逾時、背景工作可能因記憶體不足被砍，所以**一律用 `BUDGET` 分段**，並在 repo 根目錄（或任何想放結果的目錄）執行：

```bash
BUDGET=540 python3 $SK/speedtest.py all <使用者確認的國家代碼>
```

（PowerShell：`$env:BUDGET=540; python3 $SK/speedtest.py all <國家>`。國家代碼省略時會依出口 IP 自動偵測，但**一定先用 `detect` 讓使用者確認**再帶入代碼。）

依 exit code 處理：

| exit | 意義 | Claude 要做的事 |
|---|---|---|
| 0 | 完成，已產生 `REPORT.md` | 讀報告、向使用者回報（見第 3 節） |
| 3 | 時間預算用完、未完成 | **原指令再跑一次**（會自動續用同一個輸出目錄、從記錄檔續跑），重複直到 exit 0。每次可簡短回報進度 |
| 4 | 未登入（cookie 缺少或失效） | 明確告訴使用者：未登入只能測 ≤480P，結果和實際高畫質觀看不同。**問使用者**要提供新的 cookie（放進 `.env.local` 或 `BILI_COOKIE`），還是用 480P 繼續；後者加 `--allow-guest` 重跑 |
| 5 | ipinfo 的出口國家與指定國家不符 | 問使用者是否開著 VPN／代理或在漫遊；確認沒問題（例如 ipinfo 判斷錯誤）才加 `--ignore-country-mismatch` 重跑，或改正國家代碼 |
| 6 | DNS 解析器與所在地不一致（見「DNS 陷阱」） | 問使用者：改用當地 ISP DNS（`--dns <IP>`）或確認後加 `--ignore-dns-mismatch` 繼續 |
| 2 | 參數錯誤或缺前置步驟 | 看訊息修正 |

- 旗標（`--allow-guest`、`--conc` 等）會記在輸出目錄的 `state.json`，續跑時不必再給。
- 輸出目錄預設是 `<cwd>/cdn-speedtest-results/<國家>-<YYYYMMDD-HHMM>/`；12 小時內同國家未完成的目錄會自動續用。要強制重來加 `--new`，要指定位置用 `--out <目錄>`（續跑時也要給同一個 `--out`）。
- 不要同時開兩個測試程序（會互搶頻寬、污染結果）。

### 流程（`all` 依序做；每步也可單獨執行：`python3 $SK/speedtest.py <步驟> <國家>`）

1. `env`：出口 IP／國家／ISP（ipinfo.io）、登入狀態、系統 DNS 與 DNS 檢查（解析器國家、ECS，見「DNS 陷阱」）、基準 RTT、關鍵節點的解析結果與 CNAME，以及網路類型（有線／Wi-Fi／疑似行動網路、Wi-Fi 規格與訊號）與總頻寬（Cloudflare 下載／上傳，約 20 秒；用來分辨「當地網路本身慢」還是「連 B 站慢」）。可加 `--isp-dns <當地 ISP DNS>` 比較「系統 DNS vs 當地 ISP DNS」的解析是否不同。
2. `pool`：收集影片池（熱門 popular、入站必刷 precious、各年份時間窗的 WBI 搜尋深頁）。約 4–6 分鐘，可續跑。
3. `pick`：挑 **3 支快篩影片**（當前熱門、播放量最高，幾乎確定各節點都有快取）+ **10 支細測影片**（播放 高/中/低 × 發布 近/中/遠 九格 + 1 支），兩組不重複；每支在 1080P 以上隨機挑一個解析度（無 1080P 取最高）。種子預設為當下時間，記錄在 `videos.json`（`--seed` 可指定）。每次執行都重新挑片。
4. `ceiling`：用快篩影片量頻寬上限（單連線 + 4/8/16/24 連線合計），並**自動決定並行數**：`floor(上限 × 50% ÷ 典型單連線速度)`，限制在 1–8（典型單連線 = max(單連線中位數, 4 連線時平均每條)，但最多算 60 Mbps＝B 站 8K 串流碼率上限：再快播放也用不到，頂端節點被抹平成同一級沒關係，換來更多並行、更短耗時）。`--conc N` 可手動覆寫。
5. `stage1` 快篩：全部節點 × 3 支熱門 × 2MB，取中位數。淘汰從寬：保留前 80 名或 ≥ 第一名 30% 的全部（取較多者；`--keep-top`、`--keep-ratio` 可調）。
6. `stage2` 細測：保留節點 × 10 支 × 4MB，順序隨機打亂。
7. `report`：排名 + 分級、只能播熱門的節點、不穩定節點、擴充內建節點現況、依 CDN 池分散的建議前 10 名 + 預設 → `REPORT.md`、`summary.json`。

其他選項：`--timeout`（每筆連線逾時，預設 10 秒）、`--mb`（細測下載量，預設 4）、`--dns <IP>` 或環境變數 `DNS=<IP>`（節點網域改用指定 DNS 解析；在當地網路通常**不需要**，只有系統 DNS 明顯不是當地的，例如被設成不帶 ECS 的公共 DNS 時才用）。測試用：`--limit-nodes N`、`--limit-videos N`、`--quick`。

### 預期耗時

- 新加坡（≈ 670 Mbps、並行 4）：測速本身約 25–30 分鐘，加影片池約 35 分鐘，需續跑 4–5 次。
- 慢的網路（上限 < 100 Mbps、並行 1–2）可能 **超過 1 小時**：**快篩的逾時節點**（約六成節點逾時／DNS 不存在／403）佔掉大部分時間。
- 細測進行中請使用者盡量不要用網路（看影片、下載）。

## 2. 解讀結果

- **分級**（`第一梯隊／可用／差／不穩定`）比名次重要：單次量測，**只有「在不在前段、屬於哪個梯隊」可信，梯隊內的名次會每次互換**。
  - 第一梯隊：與最快「穩定」節點的差距在兩者波動範圍內（≈ 2 倍標準誤），或速度接近「上限 ÷ 並行數」。
  - 可用：≥ 最快穩定節點的 50%；差：其餘。
  - 不穩定：±sd > 平均的一半，通常是快取命中時極快、未命中極慢（海外 CDN 常見），平均值不具代表性。
- **CDN 池**：很多節點名稱不同但 CNAME 指向同一池（例：`08c`、`08ct`、`hw`、`hwo1`、`08h` 都是華為一般池 `hcdnv.biliv6.gslb.c.cdnhwc2.com`），會一起快、一起慢。報告在執行時解析 CNAME 分組；bcache `cn-*` 依 `cn-{地點}-{電信}-{叢集}` 分家族。
- **建議前 10 名**：只列「第一梯隊」與「可用」（不穩定、差都不列，不足 10 個就少列）；第一梯隊優先、其餘依平均速度；每池最多 2 個（後段自然補上不同池作備援）。**預設** = 穩定（sd ≤ 30%）、TTFB 低（≤ 第一梯隊最低 TTFB × 1.5 或 +150 ms）的第一梯隊中最快者。
- 若報告出現「⚠ 第一名速度已接近上限 ÷ 並行數」：可能互搶頻寬，用較低 `--conc` 重跑細測：刪掉該輸出目錄的 `stage2.json`、`stage2.jsonl`，再 `BUDGET=540 python3 $SK/speedtest.py stage2 <國家> --out <該目錄> --conc N`（exit 3 就重跑），最後 `report <國家> --out <該目錄>`。已完成的目錄一定要給 `--out`，否則會開新目錄。

### 已知陷阱（腳本已處理，回報時要記得）

- **只能播熱門影片的 bcache 節點**：大批中國移動 bcache 節點熱門片正常，一般／冷門片一律 403。所以細測一定用分層影片；報告另列「只能播熱門影片」。
- **海外 CDN（`akamai`、`cosov`）兩極**：熱門片命中 100–400 Mbps、其他影片 1–4 Mbps → 多半被標為不穩定，不適合當預設。
- **快取標頭不可靠**：多數節點看不出命中與否，`cosov` 400 Mbps 也標 `MISS`。「疑似未命中」= 標頭 MISS 或 TTFB > 該節點中位數 2 倍。
- **API 風控**：412 會自動退避重試；搜尋回 -352 時該組略過。每週必看（series）API 會被風控，**不要用**，影片池只用 popular / precious + WBI 搜尋。
- **快篩影片不可與細測重複**，頻寬上限也只用快篩影片量，避免把細測影片預熱進節點快取。
- **時間窗太舊的搜尋**常沒有結果（2013–2016），低播放×舊的格子可能缺，會由中播放補滿 10 支（報告的影片表會顯示實際分層）。

## 3. 向使用者回報（繁體中文）

讀輸出目錄的 `REPORT.md`，用繁體中文簡短回報：

1. 測試條件一句話（出口 ISP、上限、並行數、登入與否、耗時）。
2. **建議預設節點**與理由，和**依 CDN 池分散的建議前 10 名**（表格：節點、平均 Mbps、TTFB、分級、CDN 池）。
3. 擴充內建節點（`source` 含 `project`）在此國的表現，以及失效節點（DNS 不存在、403、逾時）。只描述本次結果，不與其他國家或過去的測試比較（跨國比較之後用各國的 `summary.json` 另外做）。
4. 提醒「單次量測、看梯隊不看名次」，以及 `REPORT.md`、`summary.json` 的路徑（`summary.json` 可之後跨國比較）。

**不要**主動修改 `src/cdn-list.json` 或擴充程式；若結果顯示應調整預設或清單，提出建議讓使用者決定。
